# Что есть что — пояснение для владельца

Шпаргалка простым языком: из чего состоит система, где что лежит и что
значат слова, которые мелькают в чате с Claude. Обновляется по мере
появления нового.

---

## 1. Из чего состоит система

| Часть | Что делает |
|---|---|
| **Эмма** | Telegram-бот. Отвечает клиентам сама: знает услуги из базы знаний, квалифицирует лида, ведёт диалог |
| **CRM-доска** | Сайт crm.borninbrazil.baby. Колонки-стадии, карточки лидов, чат с клиентом, счета — рабочее место менеджера |
| **База данных (PostgreSQL)** | Память системы: лиды, вся переписка, платежи. Бэкапится в облако Backblaze автоматически |
| **Очередь (Redis + Asynq)** | «Список дел» системы: ответить клиенту, напомнить, проверить таймер. Гарантирует, что ничего не потеряется |
| **База знаний (RAG)** | Документы про услуги и цены (docs/kb). Эмма подглядывает в них перед каждым ответом |
| **Платежи (CryptoBot)** | Выставление счетов в USDT/USDC. Оплата сама двигает карточку по доске |
| **Мониторинг** | Prometheus + Grafana: следят за здоровьем системы и шлют алерты, если что-то падает |

## 2. Три места, где живёт код

```
Мак (разработка) ──push──▶ GitHub (склад) ──pull──▶ Сервер (бой)
```

- **Мак** — здесь Claude Code пишет и проверяет код (папка `~/aicrm/interfin-ai-crm`).
- **GitHub** — облачный склад кода с историей всех изменений. Ничего не выполняет, просто хранит.
- **Сервер** (95.211.165.169) — здесь система работает для реальных клиентов. Забирает код с GitHub командой `update_bot.sh`.

Как отличить окна терминала: `amigo@MacBook-Pro %` — ты на Маке,
`root@VM-...#` — ты на сервере.

## 3. Словарь терминов

- **git** — система учёта изменений кода: кто, что и когда поменял, с возможностью откатить.
- **Ветка (branch)** — отдельная «копия» проекта для работы. Новая фича делается в своей ветке и не трогает боевой код, пока не готова.
- **Коммит (commit)** — «сохранённая точка»: пачка изменений с подписью, что сделано. Например `f87ed52 M12: manager chat`.
- **Push / pull** — отправить коммиты на GitHub / забрать их оттуда.
- **Merge (мердж)** — влить изменения одной ветки в другую (готовый эпик → в боевую ветку).
- **feat/m11-ops** — БОЕВАЯ ветка: сервер обновляется только из неё. Название историческое — эпик M11 (operations) был финальным и «обернул» систему для продакшена. Готовые эпики вливаются сюда.
- **Эпик (M0, M1… M13)** — один крупный кусок работы = один чат с Claude = одна ветка = одно ТЗ в `tasks/`.
- **Миграция** — пронумерованное изменение структуры базы данных (например 0012 добавила колонку «кто написал сообщение»). На сервере накатывается ДО обновления приложения.
- **Docker / контейнер** — «коробки», в которых изолированно работают части системы (приложение, база, Redis...). На сервере их ~15.
- **Образ (image)** — собранная «болванка» контейнера. «Пересобрать образ» = упаковать свежий код в новую коробку.
- **Деплой** — доставка нового кода на боевой сервер. У нас: миграции (если есть) → `bash scripts/update_bot.sh`.
- **Вебхук (webhook)** — «звонок» одного сервиса другому: Telegram стучится к нам при каждом сообщении клиента, CryptoBot — при оплате.
- **Воркер** — фоновый работник: разбирает очередь дел (ответы Эммы, таймеры, напоминания).
- **Промпт** — инструкция для Эммы: кто она, как отвечать, что нельзя. Сейчас зашит в код (правка = пересборка), в блоке 3 плана переедет в CRM.
- **Токены** — «слова», которыми AI меряет текст; за них идёт оплата Anthropic.
- **API-ключ / секрет** — пароль, по которому система ходит во внешние сервисы (Telegram, Claude, CryptoBot). Хранятся в `.env` на Маке и в Docker-секретах на сервере, НИКОГДА в коде. Твоя копия — `crmkeys` на Маке.
- **JWT / access-токен** — «пропуск» менеджера в CRM после входа по паролю; живёт 15 минут и продлевается сам.
- **WS (WebSocket)** — постоянное соединение доски с сервером: карточки и чат обновляются мгновенно, без перезагрузки страницы.
- **Тесты (юнит / contract / e2e)** — автопроверки кода: от «эта функция считает верно» до «живой сервер + браузер: сообщение реально дошло». Эпик не закрывается, пока все зелёные.
- **Смоук** — быстрая ручная проверка «в живую» после деплоя (написать боту, выставить счёт).

## 4. Важные файлы в проекте

| Файл/папка | Что это |
|---|---|
| `CLAUDE.md` | «Конституция» проекта: правила, которые Claude обязан соблюдать в каждой сессии |
| `tasks/M*.md` | ТЗ каждого эпика: что сделать, что НЕ делать, как проверить |
| `docs/PLAYBOOK.md` | Готовые сообщения для Claude по каждому эпику — копируй по одному |
| `docs/NEXT_STEPS.md` | План будущих фич понятным языком, с твоими решениями |
| `docs/GLOSSARY.md` | Этот файл |
| `docs/ops/deploy_steps.md` | Подробный технический runbook боевого сервера |
| `docs/kb/` | База знаний Эммы (услуги, цены, FAQ) |
| `migrations/` | Все изменения структуры базы по порядку (0001–0012...) |
| `scripts/` | Твои «кнопки» и служебные инструменты |
| `web/` | Код CRM-доски (React) |
| `internal/`, `cmd/` | Код бэкенда на Go — сердце системы |
| `.env` | Секретные ключи на Маке (в git НЕ попадает) |

## 5. Твои «кнопки» (на сервере)

| Команда | Что делает |
|---|---|
| `bash scripts/update_bot.sh` | Обновить систему: забрать код с GitHub, пересобрать, перезапустить без простоя, проверить |
| `bash scripts/update_kb.sh` | Обновить базу знаний Эммы после правки docs/kb |
| `bash scripts/new_invoice.sh <лид> <сумма>` | Запасной способ выставить счёт из терминала (основной — кнопка в CRM) |
| `crmkeys show` (на Маке) | Открыть твоё хранилище паролей и ключей |

## 6. Как рождается новая фича

1. Ты описываешь хотелку своими словами → обсуждаем.
2. Claude пишет ТЗ в `tasks/M<N>_*.md` и добавляет раздел в PLAYBOOK.
3. Ты смотришь ТЗ (особенно «Вне скоупа» и критерии) → «делаем».
4. Новый чат, сообщения из PLAYBOOK по одному: ветка → работа → проверки → коммит → мердж в `feat/m11-ops`.
5. Деплой на сервер по блоку из PLAYBOOK → ручной смоук → работает.
