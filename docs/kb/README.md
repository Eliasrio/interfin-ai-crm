# База знаний RAG (M4, SRS §7.1)

Каталог документов, из которых бот берёт факты о компании (тарифы, услуги,
процедуры). Кладите сюда `.md` / `.txt` файлы — один файл = один документ
(`source` в таблице `knowledge_chunks`).

## Индексация

```bash
# требует POSTGRES_DSN и VOYAGE_API_KEY (.env)
go run ./cmd/index-kb -dir ./docs/kb
```

Переиндексация того же файла атомарно заменяет его чанки. Удалили файл —
перезапустите индексацию оставшихся и почистите осиротевший `source` вручную,
либо проиндексируйте пустой файл с тем же именем.

## Калибровка порога (§7.1)

Тестовая выборка `testset.json` — «вопрос лида → документ, который обязан
найтись в top-5»:

```json
[
  {"query": "какие у вас тарифы?", "expected_source": "tariffs.md"},
  {"query": "как вывести средства?", "expected_source": "withdrawals.md"}
]
```

```bash
go run ./scripts/rag_calibrate -testset ./docs/kb/testset.json
```

Скрипт считает recall@5 при текущем `rag.cosine_threshold` (0.40 — временный
дефолт: SRS §7.1 задавал 0.78, но живой замер voyage-3 даёт релевантным
русскоязычным парам cosine ≈ 0.47–0.60, нерелевантным ≈ 0.20–0.27; см.
комментарий в `config/config.yaml`). Если recall < 90% — снижайте порог;
проверить кандидата: `go run ./scripts/rag_calibrate -threshold 0.35`.

Файлы самой базы знаний и `testset.json` наполняет контент-команда INTERFIN;
в репозитории их нет, чтобы не коммитить черновики фактов о компании.
