# EP-07 — Панель Эммы: React UI (PIN-экраны + 6 вкладок)

**Ветка:** `feat/ep07-ui` (от `feat/m11-ops`, включает EP-01…EP-06)
**Зависимости:** EP-01…EP-06 — весь API `/api/emma/*` готов и зафиксирован
contract-тестами; M10 (структура web/, конвенции фронта).
**Разделы ТЗ:** `docs/EMMA_PANEL_TZ_v2.md` §2 (PIN-сценарии), §3 (все
вкладки — UI-детали), §6 (какие ручки дёргать), §9 п.1–3.

## Цель
Раздел «🤖 Эмма» в CRM: виден только admin, открывается через PIN,
внутри — 6 вкладок (Промпт, База знаний, Файлы, Контакты, Сценарий,
Статистика) с общим паттерном «баннер несохранённых изменений →
Применить». Последний эпик панели — после него всё управление Эммой
доступно из браузера.

## Контекст (конвенции фронта — M10/M12/M13, не нарушать)
- Роутера НЕТ: `App.jsx` переключает экраны по состоянию; новый экран
  «Эмма» — тем же способом (кнопка в шапке доски → view='emma').
- Логика отдельно от React: `web/src/lib/emma.js` (fetch-обёртки,
  состояние PIN, счётчик токенов) + компоненты в `web/src/components/`;
  тесты vitest рядом (`*.test.js(x)`), запуск `npm test`.
- `lib/api.js` — базовый fetch с access-токеном в памяти и refresh
  single-flight; `ApiError` несёт `data` (код ошибки) — переиспользовать,
  НЕ писать свой fetch.
- Роль — `lib/auth.js` (claims.role); `manager` не должен ВИДЕТЬ кнопку
  раздела (не только получать 403).
- WS — `lib/socket.js`, события приходят всем; неизвестные типы
  игнорируются. Для вкладки БЗ слушать `emma_kb_status`.
- Счётчик токенов — ФОРМУЛА ВОРКЕРА: `len(bytes)/4`, в JS —
  `new TextEncoder().encode(text).length >> 2` (кириллица ≈ 2 байта на
  символ; наивный text.length/4 занизит вдвое — грабля из ТЗ §3).
- Коды ошибок API: PIN_REQUIRED(401), PIN_INVALID(401), PIN_LOCKED(429 +
  retry_after), PIN_ALREADY_SET(409), PIN_UNAVAILABLE(503),
  PROMPT_TOO_LONG(400), CONTACTS_LIMIT(400), FILE_TOO_LARGE(413),
  FILE_TYPE_UNSUPPORTED(400) — на каждый понятный русский текст.
- После деплоя фронта — жёсткая перезагрузка вкладки (Cmd+Shift+R),
  кэш держит старый бандл (грабля M12) — напомнить в отчёте.

## Задачи

1. **Каркас раздела:** кнопка «🤖 Эмма» в шапке (только claims.role ===
   'admin'); экран Эммы = PIN-гейт + вкладки. Выход из панели (DELETE
   pin/session) и возврат на доску. Любой ответ 401 PIN_REQUIRED от
   ручек панели → возврат на PIN-экран (сессия истекла через 30 мин).

2. **PIN-экраны** (`lib/emma.js` + `EmmaPinGate.jsx`):
   - GET pin/status при входе: не задан → экран установки (два поля,
     совпадение, ровно 6 цифр); задан, сессии нет → экран ввода;
     сессия активна → сразу вкладки;
   - PIN_LOCKED → таймер обратного отсчёта из retry_after, поля
     заблокированы; PIN_UNAVAILABLE → «Сервис временно недоступен»;
   - смена PIN — в настройках панели (старый + новый дважды).

3. **Вкладка Промпт** (`EmmaPromptTab.jsx`): textarea ≥20 строк;
   live-счётчик «≈N / L токенов» (лимит из GET, при превышении —
   красный и Применить заблокирован); теги запретных тем (Enter —
   добавить, × — удалить); стиль — select из 4; История — боковая
   панель: список версий (пагинация «показать ещё»), Просмотреть
   (read-only модалка), Восстановить с подтверждением «Вернутся текст,
   темы И стиль версии от <дата>»; после restore — перезагрузка формы.

4. **Вкладка База знаний** (`EmmaKbTab.jsx`): таблица (имя, тип, размер,
   статус: ⏳ pending / ✅ indexed (N чанков) / ❌ error с текстом);
   загрузка drag&drop + кнопка (принимать .txt/.md/.pdf); live-статус по
   WS emma_kb_status (+ fallback: refetch списка при открытии вкладки);
   Переиндексировать; Удалить с подтверждением «Эмма забудет содержимое
   файла».

5. **Вкладка Файлы** (`EmmaFilesTab.jsx`): список карточками (название,
   описание, тип/размер, тумблер Активен → PATCH); форма загрузки:
   название + описание для Эммы (обязательное, с подсказкой-примером
   «отправь, когда клиент спрашивает цены») + файл PDF/JPG/PNG;
   Удалить с подтверждением.

6. **Вкладка Контакты** (`EmmaContactsTab.jsx`): таблица (тип-иконка,
   название, значение, комментарий, Активен, порядок); добавление/
   редактирование инлайн или модалкой; счётчик «N из 30 активных»;
   CONTACTS_LIMIT → «Лимит 30 активных контактов, выключите лишние».

7. **Вкладка Сценарий** (`EmmaScenarioTab.jsx`): welcome textarea
   (пусто = отвечает Эмма-LLM, подсказка об этом), тумблер кнопки
   менеджера + текст кнопки, текст подтверждения handoff; баннер +
   Применить (PATCH scenario).

8. **Вкладка Статистика** (`EmmaStatsTab.jsx`): переключатель периода
   (день/неделя/месяц/всё время); карточки: диалоги новые/активные,
   сообщения in/out, среднее и p95 время ответа, handoff, файлов
   отправлено (+ разбивка по файлам), токены in/out и «≈ $X»
   с pricing_note мелким шрифтом; таблица ошибок (фильтр по типу,
   пагинация); блок Алерты: chat_id (подсказка «узнать: @userinfobot»),
   Сохранить, «Отправить пробный алерт» (успех/502 — тост).

9. **Общий паттерн вкладок:** локальное состояние правок, жёлтый баннер
   «⚠️ Есть несохранённые изменения» при diff с сервером, Применить →
   PUT/PATCH → тост «Сохранено, Эмма подхватит в течение 30 секунд»;
   уход со вкладки с правками — confirm.

10. **Тесты (vitest, по образцу M10):** PIN-гейт (все 4 состояния +
    lockdown-таймер); счётчик токенов (кириллица: 8-байтовая строка =
    2 токена); баннер несохранённых; kb-статус обновляется по WS-событию;
    манагер не видит кнопку раздела (рендер шапки с role=manager);
    restore-подтверждение. `npm test` и `npm run build` зелёные.

## Вне скоупа (не делать в EP-07)
- Изменения бэкенда — API готов; нашёл несоответствие → СТОП, доложить
  (не чинить бэкенд в этом эпике).
- Локализация панели (панель на русском, это интерфейс владельца).
- Мобильная вёрстка — desktop-first, как остальная CRM.
- Деплой в прод — отдельная процедура после закрытия эпика (миграции
  0016–0021, stack deploy для volume, nginx, возврат вебхука — по
  чек-листу, который готовится отдельно).

## Контракт наружу
- Панель полностью функциональна из браузера — критерий готовности
  всего модуля (ТЗ §9 целиком проверяется вживую).
- Новые компоненты не трогают Board/LeadModal — регресс доски исключён
  (кроме кнопки в шапке).
