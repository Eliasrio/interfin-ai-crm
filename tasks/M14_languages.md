# M14 — Языки клиента: русский / английский / испанский

**Ветка:** `feat/m14-languages` (от `feat/m11-ops`)
**Зависимости:** M2 (ingestion — здесь детекция первого сообщения),
M3 (processor/prompt — Эмма отвечает на языке лида), M8 (REST leadJSON),
M9 (WS), M12 (карточка лида на фронте).
**Разделы SRS:** нет — продуктовое решение владельца
(docs/NEXT_STEPS.md, блок 2.1, правка 2026-07-08; португальский —
решение владельца: НЕ нужен).

## Цель
Язык клиента определяется по его первому текстовому сообщению,
запоминается в карточке лида и виден менеджеру; Эмма ведёт весь диалог
на этом языке (включая детерминированные ответы вроде «понимаю только
текст»). Поддерживаются ровно три языка: **ru / en / es**. Менеджер может
поправить язык руками, если детектор ошибся.

## Контекст (что уже есть — переиспользовать, не дублировать)
- Inbound сохраняет ingestion (M2) — единственное место, где появляется
  первое сообщение лида; детекция локальная и быстрая, правило
  «webhook отвечает 200 немедленно» (CLAUDE.md §4.4) не нарушается.
- `internal/worker/prompt.go`: `systemPrompt` (сейчас содержит правило
  «Отвечай на русском») и `nonTextReply` (русская константа) —
  обе точки становятся языкозависимыми.
- `composeSystemPrompt` + Budgeter: system-блок обязан оставаться
  в пределах `budget.system_prompt` = 2000 токенов (§7.2) — языковая
  вставка короткая.
- Сумматор (`internal/worker/summary.go`) пишет сводку ПО-РУССКИ — это
  внутренний артефакт для менеджера, НЕ трогать (он и должен сжимать
  en/es-диалог в русскую сводку).
- RAG (M4): voyage-3 мультиязычная — запрос на en/es эмбеддится как есть
  и ищет по русской базе знаний; сам RAG-контур не трогаем.
- `events.Event` → Redis → Hub → WS: клиенты игнорируют незнакомые типы
  (проверено M12) — новый тип события безопасен.
- leadJSON в `internal/handlers/leads.go` — язык отдаётся в REST так же,
  как поля M13 (`dialog_mode` и др.).
- Роли: язык меняет manager|admin (auth.RequireRole, M7/M8), как режим M13.

## Модель языка (решение M14)
- `leads.language VARCHAR(2) NULL` CHECK `('ru','en','es')`;
  NULL = «ещё не определён» (лид ещё не прислал ни одного текста).
- Детекция срабатывает ОДИН раз: первый inbound с текстом при
  `language IS NULL`. Дальше язык не пересматривается автоматически —
  только руками менеджера (решение владельца: «по первому сообщению,
  запоминается»).
- Везде, где язык нужен, а он NULL, — fallback **ru** (основная
  аудитория русскоязычная; и так вело себя всё до M14).

## Задачи
1. **Миграция 0015** (`leads.language`) + модель Lead + schema-lint.
   LGPD: язык не идентифицирует человека — erasure не трогает; export
   отдаёт как есть.
2. **Детектор** `internal/lang` (новый пакет): `Detect(text) string`
   → 'ru'|'en'|'es'. Реализация:
   - есть кириллица → сразу 'ru' (быстрый путь, короткие «Привет» не
     доверяем триграммам);
   - иначе — `github.com/abadojack/whatlanggo` (лёгкая, без зависимостей;
     пришпилить версию) с whitelist {en, es};
   - низкая уверенность / пусто / не из тройки → 'ru'.
   Юнит-таблица: «Привет», «Hi», «Hola», «Buenas tardes, quiero info»,
   «hello, I need citizenship info», эмодзи-только, пустая строка.
3. **Ingestion (M2):** при сохранении первого текстового inbound лида
   с `language IS NULL` — определить и записать язык (в той же
   транзакции, что и сообщение). Нетекстовое первое сообщение язык
   НЕ выставляет. Опубликовать WS-событие `lead_language` (задача 5).
4. **Эмма говорит на языке лида (worker):**
   - из `systemPrompt` убрать «Отвечай на русском»; processor добавляет
     к system-блоку языковую инструкцию по `lead.Language` (NULL → ru):
     «Отвечай на <русском|английском|испанском>; если клиент явно просит
     другой язык из тройки — переходи, но карточку меняет менеджер»;
   - `nonTextReply` → три локализованные версии (ru/en/es), выбор по
     языку лида (NULL → ru) — и в ветке нетекстового, и в переотправке.
5. **WS-событие `lead_language`** {lead_id, language, ts} — публикуется
   при автодетекции (задача 3) и ручной смене (задача 6). По образцу
   `dialog_mode`: событие несёт состояние целиком.
6. **`PATCH /api/leads/:id/language`** `{"language":"ru"|"en"|"es"}`
   (manager|admin): идемпотентно (повтор — 200), мусор — 400,
   стёртый/нет лида — 404; публикует `lead_language`. `language`
   добавить в leadJSON (`GET /api/leads`).
7. **Фронт (web/):**
   - бейдж языка на карточке и в модалке лида: 🇷🇺 RU / 🇬🇧 EN / 🇪🇸 ES,
     NULL — не показывать; live по WS `lead_language`;
   - в модалке — выпадающий выбор языка (ru/en/es) → PATCH, disabled на
     время запроса;
   - неизвестные типы событий по-прежнему игнорируются молча.

## Вне скоупа (не делать в M14)
- Португальский и любые другие языки — решение владельца: только ru/en/es.
- Автоматическая смена языка по ходу диалога (клиент перешёл на другой
  язык) — язык фиксируется первым сообщением, дальше только руками.
- Перевод интерфейса CRM — CRM остаётся русской, язык касается только
  диалога Эммы с клиентом.
- Локализация/перевод базы знаний и сводок — база русская, сводка
  русская; Эмма отвечает на языке клиента, опираясь на них.
- Свежесть базы знаний (блок 2.2 NEXT_STEPS) — отдельный эпик.
- Управление списком языков из CRM (блок 3, Command Center) — M15;
  здесь тройка зашита constant'ой.

## Контракт наружу
- Новый WS-тип `lead_language` — старые клиенты обязаны молча
  игнорировать (уже проверено тестом M12).
- `PATCH /api/leads/:id/language` — новая ручка; `language` — новое поле
  в `GET /api/leads`.
- Поведение M3 меняется: язык ответа Эммы зависит от `leads.language`.
  Тесты, ждущие русских ответов, не ломаются: русские сообщения дают
  'ru', NULL даёт fallback 'ru'.

## Критерии приёмки
- [ ] Первое сообщение «Hola, quiero la ciudadanía» → в карточке ES,
      ответ Эммы испанский; «Hi, I need info» → EN, ответ английский;
      «Привет» → RU (contract-тест processor с фейковым Claude:
      проверяем языковую инструкцию в system-блоке; юнит-таблица
      детектора из задачи 2).
- [ ] Второе сообщение на другом языке язык в карточке НЕ меняет
      (contract-тест ingestion).
- [ ] Первое сообщение — голосовое: язык не выставлен, подсказка
      «понимаю только текст» на русском; лид с language='es' шлёт
      стикер — подсказка испанская (contract-тест).
- [ ] PATCH /api/leads/:id/language: manager меняет (200, идемпотентно),
      мусор («pt», «», 123) — 400, стёртый лид — 404; событие
      `lead_language` доходит до второй вкладки live (e2e).
- [ ] Бейдж языка виден на карточке и в модалке; ручная смена через
      выпадающий список работает (e2e).
- [ ] System-блок с языковой вставкой укладывается в бюджет §7.2
      (существующие тесты Budgeter зелёные).
- [ ] `go build ./...`, `go vet ./...`, gofmt, schema-lint,
      юнит+интеграционные `-p 1`, `npm test`, e2e — зелёные.
