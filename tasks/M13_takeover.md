# M13 — Human Takeover: «Взять в работу» + напоминания об ожидающих

**Ветка:** `feat/m13-takeover` (от `feat/m11-ops`)
**Зависимости:** M3 (processor/Sender), M5 (события crm:events), M8 (REST+auth),
M9 (WS), M12 (чат из карточки, messages.author).
**Разделы SRS:** нет — продуктовое решение владельца
(docs/NEXT_STEPS.md, блоки 1 и 2.3, правки 2026-07-08; идея режимов —
Architecture v1.1 §3, BUG-01/LOGIC-01, адаптирована под личку без userbot).

## Цель
Менеджер одной кнопкой забирает диалог у Эммы и возвращает обратно; Эмма
никогда не перебивает менеджера (в т.ч. при гонке «уже генерирует ответ»);
клиент не висит без ответа: 10 минут тишины → напоминание менеджеру, ещё
10 минут → Эмма подхватывает сама. Все интервалы — настройки в CRM.

## Контекст (что уже есть — переиспользовать, не дублировать)
- `POST /api/leads/:id/messages` (M12) — реплика менеджера; сюда встраивается
  автопилот (пауза Эммы после реплики менеджера).
- `worker.Processor.HandleProcessInbound` — единственное место, где Эмма
  отвечает; там же ветка переотправки и nonTextReply — все точки отправки
  обязаны уважать режим.
- `events.Event` → Redis → Hub → WS: клиенты игнорируют незнакомые типы
  (проверено M12) — новые типы событий безопасны.
- Асинхронные таймеры — Asynq по образцу TTL (M5): TaskID+Unique
  (CLAUDE.md §4.5), отмена — `inspector.DeleteTask`.
- Уведомления менеджеру в Telegram — `Sender` + `cfg.Telegram.ManagerChatID`
  (контур алертов dead letter, M3/M11).
- Роли: настройки меняет только admin (auth.RequireRole, M7/M8).

## Модель режима (решение M13)
В БД два поля вместо тройного enum (hybrid — вычислимое состояние):
- `leads.dialog_mode VARCHAR(8) NOT NULL DEFAULT 'bot'` CHECK `('bot','human')`;
- `leads.bot_silenced_until TIMESTAMPTZ NULL` — «Эмма молчит до» (автопилот);
- `leads.taken_by BIGINT NULL` — id менеджера, взявшего диалог (для UI и
  напоминаний).
UI-состояния: `human` → «✋ ведёт менеджер»; `bot` + silenced_until в будущем
→ «⏸ Эмма на паузе до HH:MM»; иначе «🤖 ведёт Эмма».

## Задачи
1. **Миграция 0013** (`dialog_mode`, `bot_silenced_until`, `taken_by`) +
   модель Lead + schema-lint. LGPD: поля лида не идентифицируют — erasure
   не трогает; export отдаёт как есть.
2. **Таблица `settings` (миграция 0014)** — key/value (VARCHAR/TEXT),
   фундамент «полного управления Эммой» (блок 3): ключи M13 —
   `takeover.hybrid_pause_minutes` (дефолт 30),
   `takeover.reminder_minutes` (10), `takeover.pickup_minutes` (10).
   Репозиторий SettingsRepo (Get с дефолтом, Set), кэш на 30 сек.
   `GET /api/settings` (manager|admin — читать), `PATCH /api/settings`
   (только admin), валидация: минуты 1..1440.
3. **`PATCH /api/leads/:id/mode`** `{"mode":"bot"|"human"}` (manager|admin):
   - → human: `taken_by` = sub из JWT, `bot_silenced_until` = NULL;
   - → bot: `taken_by` = NULL, пауза снимается;
   - идемпотентно (повтор того же режима — 200), 404 стёртый/нет лида;
   - WS-событие `dialog_mode` {lead_id, mode, silenced_until, taken_by, ts}.
4. **Автопилот (hybrid):** в `POST /api/leads/:id/messages` и в ручке счёта
   после успешной отправки, если `dialog_mode='bot'`: выставить
   `bot_silenced_until = NOW() + hybrid_pause_minutes` и опубликовать
   `dialog_mode` (mode='bot', silenced_until заполнен). В режиме human
   пауза не трогается.
5. **Эмма уважает режим (BUG-01, двойная проверка):**
   - в начале HandleProcessInbound: режим human или активная пауза →
     сохранённый inbound остаётся, Kanban-триггеры (§3.2/3.5) отрабатывают,
     Claude НЕ вызывается, взводится контур напоминаний (задача 6);
   - **непосредственно перед CreateOutbound** (ответ Эммы и nonTextReply):
     перечитать режим из БД; изменился на human/паузу за время генерации →
     ответ отбрасывается БЕЗ записи в messages и без Send, задача
     завершается успешно (не ретрай). Ветку переотправки это не ломает:
     несохранённый ответ не переотправляется.
   - Авто-снятие просроченной паузы: silenced_until в прошлом = режим bot,
     отдельного крона не требуется (проверка по месту).
6. **Напоминания и подхват (LOGIC-01, тайминги владельца 10+10):**
   на каждый inbound при режиме human/паузе — Asynq-задача
   `takeover:reminder` через reminder_minutes (TaskID: lead+message_count,
   Unique — дубль апдейта не плодит напоминаний):
   - обработчик: менеджер уже ответил (последний outbound
     `author LIKE 'manager:%'` новее этого inbound) или режим снова bot →
     no-op; иначе: уведомление менеджеру в Telegram (ManagerChatID) +
     WS-событие `takeover_reminder` {lead_id, waiting_minutes} + постановка
     `takeover:pickup` ещё через pickup_minutes;
   - `takeover:pickup`: если менеджер так и не ответил → dialog_mode='bot',
     пауза снята, `taken_by`=NULL, enqueue `process:inbound` (Эмма отвечает
     штатным контуром), уведомление менеджеру «Эмма подхватила лид #N»,
     WS `dialog_mode`;
   - клиент прислал НОВОЕ сообщение до срабатывания — старые задачи
     становятся no-op сами (проверка «менеджер ответил после инициирующего
     inbound» смотрит на факт, а не на конкретный message_id), новые
     взводятся заново.
7. **Фронт (web/):**
   - индикатор режима над чат-панелью карточки: 🤖 / ✋ (кто взял) /
     ⏸ (до какого времени), live по WS `dialog_mode`;
   - кнопки «✋ Взять в работу» / «🤖 Вернуть Эмме» (disabled на время
     запроса);
   - тост по `takeover_reminder` («Лид N ждёт ответа M минут») и по
     подхвату Эммы;
   - страница/секция «Настройки» (видна admin): три интервала M13,
     сохранение через PATCH /api/settings;
   - неизвестные типы событий по-прежнему игнорируются молча.

## Вне скоупа (не делать в M13)
- Userbot, Telegram-группы, мультибот — отложено (docs/NEXT_STEPS.md).
- Языки клиента (блок 2.1) — M14.
- Полный Command Center (промпт/база знаний из CRM, cost tracker) — M15;
  здесь только таблица settings и три интервала.
- Шаблоны ответов и подсказки Эммы — блок 4.
- Права «кто может брать чужого лида» — любой manager может всё, как в M8.

## Контракт наружу
- Новые WS-типы `dialog_mode`, `takeover_reminder` — старые клиенты обязаны
  их молча игнорировать (уже проверено тестом M12).
- `PATCH /api/leads/:id/mode`, `GET/PATCH /api/settings` — новые ручки /api.
- Поведение M3 меняется: Эмма молчит в human/паузе — e2e бота, ждущие
  автоответа, обязаны выставлять режим bot в сетапе.

## Критерии приёмки
- [ ] Кнопка «Взять в работу»: после неё inbound клиента НЕ порождает ответ
      Эммы (contract-тест processor + e2e по образцу m12).
- [ ] Гонка BUG-01: режим сменился на human ПОСЛЕ старта генерации → в
      messages НЕТ ответа Эммы, в Telegram ничего не ушло (contract-тест
      с фейками: смена режима между Complete и CreateOutbound).
- [ ] Реплика менеджера из карточки при режиме bot ставит паузу
      hybrid_pause_minutes; после истечения Эмма снова отвечает
      (contract-тест с подменой NOW через настройку в 0 минут — e2e).
- [ ] Клиент ждёт reminder_minutes в режиме human → менеджеру уходит
      Telegram-уведомление и WS-событие; ещё pickup_minutes → Эмма
      подхватывает: режим bot, ответ клиенту, уведомление менеджеру
      (интеграционный тест с интервалами в секундах через settings).
- [ ] Менеджер ответил внутри окна → ни напоминания, ни подхвата (no-op).
- [ ] PATCH /api/settings: admin меняет интервалы (200), manager — 403;
      мусор (0, -5, «abc») — 400.
- [ ] Индикатор режима в карточке меняется live во второй вкладке без
      перезагрузки (e2e).
- [ ] `go build ./...`, `go vet ./...`, gofmt, schema-lint, юнит+интеграционные
      `-p 1`, `npm test`, e2e — зелёные.
