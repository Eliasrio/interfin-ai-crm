# EP-02 — Панель Эммы: промпт из БД, история версий, лимит токенов

**Ветка:** `feat/ep02-prompt` (от `feat/m11-ops`, включает EP-01 `b1ed7d7`)
**Зависимости:** EP-01 (таблица emma_prompt_versions, модель EmmaPromptVersion,
защищённая группа emmaProtected, settings.String + KeyPromptTokenLimit),
M3 (prompt.go/Budgeter), M14 (languageInstruction).
**Разделы ТЗ:** `docs/EMMA_PANEL_TZ_v2.md` §3 «Вкладка 1 — Промпт»,
§0 (бюджет 2000→5000), §6 (группа prompt), §7, §9 п.3.

## Цель
Системный промпт Эммы редактируется из панели: хранится в БД с неограниченной
историей версий и откатом, включает запретные темы и стиль общения; воркер
подхватывает изменения без рестарта (кэш ≤30 с); бюджет system-блока поднят
до 5000 токенов под будущие секции (контакты EP-05, файлы EP-04, RAG).

## Контекст (что уже есть — переиспользовать, не дублировать)
- `internal/worker/prompt.go` — константа `systemPrompt` (~1900 байт ≈ 850
  токенов по метрике len/4), `languageInstruction` (M14, остаётся кодом),
  `composeSystemPrompt(base, chunks)` (RAG-хвост, не трогать сигнатуру).
- **Нюанс:** правила про счета менеджера (M12) — ВНУТРИ константы, отдельной
  код-вставки нет. Они уезжают в БД вместе с текстом и становятся
  редактируемыми владельцем — это осознанно (ТЗ §3 п.5 сборки уточняется
  этим task-файлом); contract-тест M12 `TestPromptBuild_ManagerOutbound...`
  адаптировать под провайдер.
- `worker.Budgeter` — метрика `estimateTokens = len(bytes)/4`; кириллица
  ~2 байта/символ. Валидация лимита промпта — ЭТОЙ ЖЕ формулой (единая
  правда для API и воркера; выставить наружу хелпер, не дублировать).
- `internal/settings` — паттерн кэша 30 с; `String(ctx, KeyPromptTokenLimit)`
  (дефолт "1200") уже работает (EP-01).
- `emmaProtected` группа в `cmd/server/main.go` (EP-01) — ручки вешать сюда.
- Конвенция ошибок `{"error","code"}`; claims — `auth.ClaimsFrom(c)`
  (`sub` → created_by).
- Фейки MessageRepo/прочего в тестах воркера — при новом интерфейсе
  провайдера промпта готовься править все фейки (грабля M14 №3).

## Задачи

1. **Репозиторий `EmmaPromptRepo`** (internal/repo):
   - `GetCurrent(ctx)` — активная версия (is_current);
   - `CreateVersion(ctx, v)` — в одной транзакции: снять is_current со
     старой активной, вставить новую с is_current=true (частичный
     уникальный индекс 0016 — вторая активная невозможна, конфликт =
     ошибка транзакции, не молчаливая перезапись);
   - `History(ctx, page, perPage)` — id, created_at, created_by, первые
     100 символов промпта (обрезка по рунам, не байтам — кириллица),
     style; сортировка новые→старые; total для пагинации;
   - `GetByID(ctx, id)` — полная версия.
   Восстановление = `CreateVersion` с копией полей версии-источника
   (старая активная остаётся в истории автоматически — отдельного
   «ухода в историю» не существует, строки не мутируются).

2. **Провайдер промпта для воркера** (internal/emma или internal/worker):
   `PromptProvider.Current(ctx) (PromptConfig, error)` — кэш 30 с
   (паттерн settings); `PromptConfig{Text, ForbiddenTopics []string,
   Style string}`. Таблица пуста → fallback на константу `systemPrompt`
   (константа помечается deprecated-комментарием, НЕ удаляется).

3. **Сборка system-блока** в prompt.go: базовый текст из провайдера +
   секция запретных тем (только если список непуст):
   `«Никогда не обсуждай следующие темы: …. Вежливо возвращай разговор к
   услугам сервиса.»` + секция стиля (neutral → без вставки; formal /
   friendly / expert — по короткой фразе-вставке) + languageInstruction
   (M14, как было) + composeSystemPrompt(chunks) (как было).
   Порядок — ТЗ §3 «Сборка system-блока».

4. **Seed-миграция 0021**: INSERT текста текущей константы как версия 1
   (is_current=true, style='neutral', topics '[]', created_by NULL)
   с guard'ом `WHERE NOT EXISTS (SELECT 1 FROM emma_prompt_versions)` —
   идемпотентно и не затирает данные, если владелец уже сохранял версии.
   Down — no-op (данные не откатываем).

5. **Бюджет 5000** (решение владельца, ТЗ §0/§10 п.6):
   `config/config.yaml` `token_budget.system_prompt: 2000 → 5000`
   (+ комментарий-обоснование: секции панели + RAG; итог входа 11000).
   Обновить CLAUDE.md §4.6-соседний блок: строка об отклонении от SRS §7.2
   по образцу записи о замене модели (§3). Проверить: threshold 7500
   теперь МЕНЬШЕ возможного system-блока — точный count_tokens будет
   вызываться чаще; это ок, но убедиться тестом, что Build не ломается
   при system > threshold.

6. **API на emmaProtected** (ТЗ §6):
   - `GET /prompt` → `{version_id, system_prompt, forbidden_topics, style,
     created_at, token_estimate, token_limit}`;
   - `PUT /prompt` `{system_prompt, forbidden_topics, style}` →
     валидация: непустой текст; style из enum (иначе 400); оценка токенов
     ТЕКСТА промпта ≤ лимита из settings → иначе 400
     `{"code":"PROMPT_TOO_LONG", "estimate":N, "limit":M}`;
     успех → новая версия (created_by = sub), 200 с телом как GET;
   - `GET /prompt/history?page=` → `{items:[{id, created_at, created_by,
     preview, style}], total, page}`; 50 на страницу;
   - `GET /prompt/history/:vid` → полная версия; 404 на чужой/нет id;
   - `POST /prompt/history/:vid/restore` → новая активная версия — копия
     vid, 200 с телом как GET /prompt.

7. **Аудит**: PUT и restore логируются (manager_id, version_id) — Audit-
   middleware EP-01 уже пишет след, добавить version_id в тело лога ручек.

## Вне скоупа (не делать в EP-02)
- Секции контактов и файлов в system-блоке — EP-05 и EP-04 (сборка в
  prompt.go должна быть расширяемой: список секций, а не склейка строк).
- Маркер-парсер, инструкция про {{handoff}}/{{file:N}} — EP-04/EP-05.
- Счётчик токенов в UI — EP-07 (но token_estimate/token_limit в GET —
  здесь, фронту останется отрисовать).
- LLM-классификатор запретных тем — вне v1 (ТЗ §3).

## Контракт наружу
- `PromptProvider.Current(ctx)` — EP-04/EP-05 добавляют свои секции рядом,
  в той же точке сборки prompt.go.
- Ручки `/api/emma/prompt*` — фронт EP-07.
- `token_budget.system_prompt=5000` — общий для всех последующих эпиков;
  EP-05 (контакты ≤30) и EP-04 (описания файлов) считают на него.
- Seed 0021: на живом проде первая версия = текущий боевой промпт,
  поведение Эммы при деплое НЕ меняется.

## Критерии приёмки
- [ ] PUT /prompt создаёт новую версию; в БД ровно одна is_current
      (интеграционный тест: параллельные PUT не дают двух активных).
- [ ] Изменённый через API промпт попадает в system-блок следующего
      запроса к Claude без рестарта, в пределах TTL кэша ≤30 с
      (contract-тест processor с фейком Claude: правка → тик кэша →
      system содержит новый текст).
- [ ] Restore версии N: активной становится копия N (все три поля:
      текст, темы, стиль); прежняя активная видна в истории.
- [ ] PUT с текстом > лимита (сгенерировать >1200 токенов ≈ >9600 байт
      кириллицы) → 400 PROMPT_TOO_LONG с estimate и limit; после
      SetString лимита 2000 тот же текст проходит.
- [ ] Пустая таблица (свежая БД без 0021) → воркер работает на константе
      (unit на fallback провайдера).
- [ ] Миграция 0021 на dev-БД: GetCurrent = текст константы; Эмма отвечает
      как до эпика (живой смоук одним сообщением).
- [ ] Секция запретных тем появляется в system-блоке при непустом списке
      и отсутствует при пустом; стиль neutral не добавляет текста
      (unit prompt.go).
- [ ] Budgeter с system_prompt=5000 собирает запрос, history не съедена
      (unit: system 4900 токенов + история → inputLimit 11000 соблюдён).
- [ ] Manager → 403, admin без PIN → 401 на всех ручках prompt
      (contract-тест группы).
- [ ] CLAUDE.md обновлён (бюджет 5000); `go build`, `go vet`,
      `go test -p 1` зелёные, включая старые prompt-тесты M12/M14
      (адаптированы под провайдер).
